## Columns used

The CSV contains the following six columns:

- `Price` — date column in this export, despite the slightly confusing name;
- `Close` — daily closing price;
- `High` — daily high price;
- `Low` — daily low price;
- `Open` — daily opening price;
- `Volume` — reported daily volume.

The first three rows are metadata/header rows rather than observations:

1. column labels;
2. ticker labels;
3. the date-level label.

The actual observations begin on the fourth physical row, with the date `2018-01-01`. These three metadata rows must be removed or parsed correctly before feature engineering.

## Price-adjustment method

The CSV does not contain a separate `Adj Close` column and does not record the exact `yfinance` download options. Therefore, the adjustment setting cannot be proven from the file alone.

For this project, record the download setting in the data-collection notes. Bitcoin does not have stock-style dividends or splits, so the usual adjusted-close issue is less important than it would be for an equity. Nevertheless, the exact source settings should be documented for reproducibility.

## Missing-data decisions

No missing values were found in the actual observation rows, so no numerical values were imputed.

The three metadata rows at the top of the CSV are not observations and must be excluded from the analytical dataset. They are structural rows, not missing market data.

The last available date is `2025-12-30`. Do not describe the file as containing every date through `2025-12-31` unless that date is actually present.

## Known limitations

1. **Daily aggregate data** — OHLCV data does not contain the intraday path of BTC prices.
2. **24/7 market** — Bitcoin trades on weekends, unlike conventional stock-market data. Use “daily periods” rather than “trading days”.
3. **Timezone is not recorded** — the CSV contains dates but no timestamp or timezone. Record the timezone used by the data provider if available.
4. **Volume interpretation** — Yahoo Finance volume is an aggregate reported by the provider and should not be treated as the complete volume of every cryptocurrency exchange.
5. **Source dependency** — Yahoo Finance is convenient for research and education, but data availability, corrections and formatting can change.
6. **No transaction costs** — this dataset does not include bid–ask spreads, fees, slippage or execution delays.
7. **No survivorship issue for BTC itself** — the project studies one continuously existing asset, but the result may not generalise to other crypto-assets.
8. **Non-stationarity** — Bitcoin’s volatility and market structure changed substantially between 2018 and 2025.
9. **Potential data revisions** — a later download may not be byte-for-byte identical to this CSV. Preserve the retrieval date and file hash when the dataset is finalised.

## Project decision

This dataset is suitable for the first BTC-USD version of the Market Regime and Risk Lab.

Use the following wording in the experiment protocol:

> We use daily BTC-USD OHLCV data retrieved from Yahoo Finance through `yfinance`, covering 1 January 2018 to 30 December 2025. The dataset contains 2,921 chronological observations and no missing values after excluding the three metadata rows generated by the CSV export. Because Bitcoin trades continuously, forecast horizons are expressed in daily periods rather than trading days.

Before modelling, create a cleaned analytical table with one row per date and the six named variables documented above. Do not mix this dataset with SPY or another asset in the first experiment.
